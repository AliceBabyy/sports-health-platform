# 身材数据导入 · 格式选型与落地设计

## 结论

- **主推：Excel 模板**（面向用户手动批量补录历史数据）
- **补充：JSON**（备份恢复 / 跨端同步 / API 导入，保真且带元数据）
- **轻量备选：CSV**（第三方工具导出、内部自用，零依赖）
- “元数据”不是一种导入格式，而是导入方案中的 schema 定义：列名→字段映射、单位、类型、模板版本。模板表头 / JSON 字段定义即元数据；模板版本号用于支持表头改名后旧文件仍可导入。

## 格式对比（主观评估）

| 维度 | Excel 模板 | CSV | JSON |
| --- | --- | --- | --- |
| 用户填写/修改友好度 | 高 | 中 | 低 |
| 解析实现成本 | 中（openpyxl/pandas） | 低（标准库 csv） | 低（json） |
| 校验与错误定位 | 高（行号+列名） | 中 | 中 |
| 单位/示例随文件携带 | 高（模板即文档） | 低 | 中 |
| 元数据保真（created_at、来源等） | 低 | 低 | 高 |
| 最适用场景 | 用户手动补录历史 | 第三方导出·轻量 | 备份/跨端同步 |

## 落地设计要点（对应当前 4 表拆分模型）

1. **模板结构**：一个 xlsx 两个 Sheet，复用 `app/core/constants.py::BODY_FIELDS` 的中文标签与单位：
   - Sheet「基础记录」：`日期 | 身高(cm) | 体重(kg) | 体脂率(%)`
   - Sheet「维度记录」：`日期 | 颈围 | 肩宽 | 臂围 | 胸围 | 腰围 | 臀围 | 大腿围 | 小腿围`（单位 cm）
   - 首行表头 = 元数据（标签+单位），服务端按列名映射到 DB 列。
2. **统一处理管线**：上传文件 → 解析为统一中间结构 `List[Dict]`（按 basic/girth 分组）→ Pydantic 逐行校验（日期格式、数值范围、单位）→ 复用现有分组 upsert（`(user_id, record_date)` 同日覆盖）→ 返回「成功 N 行 / 失败 M 行 + 行号列号明细」。
3. **空值语义**：现有逻辑是「留空自动沿用该维度最近一次非空值」——导入行留空同样会触发继承。若希望「以导入文件为准、留空即置空」，需要加严格模式开关，需产品确认。
4. **幂等**：与页面保存一致，同日重复导入 = 覆盖当日该组，不会重复累积。
5. **规模**：几千行一次事务即可；上万行拆批 + 异步任务 + 进度反馈。
