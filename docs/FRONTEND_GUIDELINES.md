# 前端设计与实现规范

本文档记录已实现页面的组织方式，以及新增页面应复用的视觉、布局和交互规范。系统整体架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 页面组织

- 页面模板位于 `app/templates`，公共布局由 `base.html` 提供；公共行为位于 `app/static/js/common.js`。
- 页面资源按模块放在 `app/static/css/pages/` 和 `app/static/js/`，通过 `extra_css`、`extra_js` 按需加载。
- 业务页复用 `render_page` 注入登录用户、导航高亮、面包屑、今日信息和常量。
- 三个运动页面统一提供计划、记录、导入和记录管理入口；状态记录页和 AI 助手页按各自业务流程组织。

## 视觉与组件规范

- 颜色、圆角、间距和状态色统一定义在 `tokens.css`；CSS 使用 `var(--令牌)`，JS/ECharts 使用 `App.cssVar`。
- 页面沿用系统字体、公共按钮、输入框、标签、卡片、表格、分页、空态和弹窗组件，不重复实现公共交互。
- 计划态使用 `--state-plan`，记录态使用 `--state-record`；运动编码色使用各自语义令牌，不得用品牌色替代。
- 缺失数据显示“—”，空列表使用空态，不使用假数据占位。
- 用户文本插入 HTML 前必须经过 `App.escapeHtml`；接口请求和提示统一使用 `App.api`、`App.postMultipart`、`App.toast`。

## 布局与响应式

- 业务页沿用固定侧栏、顶栏和内容区布局；主操作紧邻页面标题，内容按任务分区排列。
- 宽表只允许表格容器横向滚动，不得撑宽整页；弹窗必须限制宽度和高度。
- 页面必须适配桌面、中屏和窄屏；标题、工具栏、表单、表格、弹窗及动态内容在窄屏仍可操作，不得互相遮挡。
- 新增页面应优先复用现有布局和组件，只有现有结构无法满足需求时才增加模块级样式。

## 静态资源与图表

- ECharts 使用本地 vendor 版本；图表颜色从 CSS 令牌运行时读取，不在 JS 中维护十六进制颜色副本。
- 静态资源 URL 带版本参数；资源修改后同步更新版本，避免浏览器缓存旧文件。
