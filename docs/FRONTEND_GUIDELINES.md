# 前端设计与实现规范

本文档记录已实现页面的组织方式，以及新增页面应复用的视觉、布局和交互规范。系统整体架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 页面组织

- 页面模板位于 `app/templates`，公共布局由 `base.html` 提供；公共行为位于 `app/static/js/common.js`。
- 页面资源按模块放在 `app/static/css/pages/` 和 `app/static/js/`，通过 `extra_css`、`extra_js` 按需加载。
- 业务页复用 `render_page` 注入登录用户、导航高亮、面包屑、今日信息和常量。
- 三个运动页面统一提供计划、记录、导入和记录管理入口；状态记录页和 AI 助手页按各自业务流程组织。
- 技能管理页 `/agent/skills` 挂在侧栏「AI助手」分组下，`active=agent_skills`，分组头与子项同时高亮；页面与 AI 对话页一致，为整页白底铺满、左侧技能导航 + 右侧编辑区的连续工作台，无外层灰底与卡片，窄屏在 640px 以下才纵向堆叠；交互与样式分别由 `agent_skills.js`、`agent_skills.css` 承载。
- 状态记录页为三卡片纵向堆叠（`three-row-stack`，卡片与内容随宽度自适应铺满）：月历 → 当日状态 → 全部记录。「当日状态」是四类块（食欲 / 肌肉疼痛 / 炎症 / 情绪）的就地填写区，每块内联星级（五星 + 「0」最低分按钮，未评存空）+ 自适应高度描述框 + 保存，有记录时块内可删除；新增记录不弹窗，仅列表行内「编辑」走表单弹窗。
- 报告页 `/reports` 挂在侧栏「运动训练/计划」分组第四项，`active=reports`；顶部 `.seg` 切周报/月报，`.date-nav` 步进周期（周 ±7 天、月 ±1 月，下一周期为未来时禁用），右侧显示「进行中 · 截至 X」与生成/重新生成按钮。主体依次为 4 张 `.stat-card`（次数/时长/活跃天数/热量，delta 文案来自服务端）、叙事卡（headline/summary/周期视角/亮点/留意/下阶段建议/数据说明）、判断依据卡（运动/身体/状态/周期/完整度）、历史报告表（查看 + 软删除）。总览页顶部提供「周报」「月报」两个 `btn btn-sm` 入口。页级脚本 `report.js`、样式 `css/pages/report.css`。
- 生理周期页 `/cycle`：左侧月历 + 月经记录，右侧当日详情；详情依次为日期/阶段标签、激素水平、疼痛程度、周期概览。激素文案由服务端按阶段日序给出，固定两行（`.dd-hormone` 用 `white-space: pre-line` 原样换行），不展示「运动建议」；疼痛星级只在经期 / 推算经期 / 预测经期（`period_state` 非空）出现，其他阶段整块隐藏。

## 视觉与组件规范

- 颜色、圆角、间距和状态色统一定义在 `tokens.css`；CSS 使用 `var(--令牌)`，JS/ECharts 使用 `App.cssVar`。
- 页面沿用系统字体、公共按钮、输入框、标签、卡片、表格、分页、空态和弹窗组件，不重复实现公共交互。
- 计划态使用 `--state-plan`，记录态使用 `--state-record`；运动编码色使用各自语义令牌，不得用品牌色替代。
- 状态记录类型标签固定四色：食欲 `tag-appetite`（橙）/ 肌肉疼痛 `tag-gray`（中性灰）/ 炎症 `tag-inflam`（红）/ 情绪 `tag-mood`（低饱和紫），底色、文字色、圆点分别取自 `--tag-*-bg` / `--tag-*-fg` / `--tag-*-dot`。
- 缺失数据显示“—”，空列表使用空态，不使用假数据占位。
- 报告页 delta 文案不使用 `delta-up/down` 的红绿语义（训练量上升不一定是“坏”）：统一 `.rp-delta` 灰色，仅上升用 `--color-accent-strong` 强调；周期视角块用 `--phase-menses` 左侧竖线，不使用整块彩色背景。
- 用户文本插入 HTML 前必须经过 `App.escapeHtml`；接口请求和提示统一使用 `App.api`、`App.postMultipart`、`App.toast`。

## 布局与响应式

- 业务页沿用固定侧栏、顶栏和内容区布局；主操作紧邻页面标题，内容按任务分区排列。
- 宽表只允许表格容器横向滚动，不得撑宽整页；弹窗必须限制宽度和高度。
- 页面必须适配桌面、中屏和窄屏；标题、工具栏、表单、表格、弹窗及动态内容在窄屏仍可操作，不得互相遮挡。
- 新增页面应优先复用现有布局和组件，只有现有结构无法满足需求时才增加模块级样式。
- 报告页：hero 为「左叙事 + 右生成信息/操作」两列，叙事分区两列（亮点/留意），下阶段建议与数据说明跨两列；<=1100px 叙事分区与依据卡转单列，<=640px hero 转单列。依据卡为 2 列网格（`rp-ev`），每块内 `rp-ev-row` 左标签右数值，窄屏单列。
- AI 助手页：空会话时欢迎语与输入框在对话区成组垂直居中，出现消息后输入框沉底；模型选择位于输入框底行、发送按钮左侧；输入框为描边叠加轻外阴影，不另设卡片底色。空态欢迎页输入框较高；进入对话后默认高度比空态低 1/3，输入换行随内容自动增高，最高不超过半屏（50vh）。正文列与输入框同宽、居中并左右对齐；AI 正文按 Markdown 渲染、无气泡描边，相邻段落以发丝灰线分隔；宽表只在表格容器内横向滚动，不撑宽正文区。每条完成的 AI 回答正文下方置灰色圆形小图标按钮（复制、重新生成），悬浮提示对应文案；复制取该条回答原始 Markdown 纯文本，重新生成仅作用于最近一轮。会话项尾部为三点按钮，弹出 body 级菜单（重命名、删除会话）；删除先弹确认框提示不可找回，确认后硬删除。输入框 placeholder 提示 `/技能名 自然语言`；输入 `/` 时在输入框上方浮出当前可用技能建议（平台与我的 active 技能），按名称/键/别名过滤，↑↓ 选择、Enter/Tab 插入 `/技能名 `、Esc 或继续输入正文后关闭，建议面板不占对话区高度；斜杠技能轨迹显示“正在运行/已运行”，技能结果折叠区展示技能名、版本、期间、输出表、caveats 和解析 meta；提示词技能折叠区只显示“已加载技能提示词，按指令生成回答”与耗时，不渲染空输出表；普通只读工具仍显示“正在查询/已查询”。
- 技能管理页：整页白底铺满，左侧技能导航与右侧编辑区以发丝线分隔，不设页面灰底、外层卡片、阴影或悬浮面板。左侧为平台/我的技能分组、数量、状态与斜杠命令，顶部为「新建技能」入口；右侧为固定工作头（技能名、斜杠命令、实现类型与版本），中间编辑器独立滚动，底部操作条作为工作区 footer 常驻，不再吸底悬浮。平台技能字段只读（`can_edit=false`），用户技能按状态显示草稿/已发布/已停用，删除权限单独由 `can_delete` 控制。用户技能只编辑提示词文本域；平台代码/声明式技能只读展示定义，不提供用户声明式模板、格式化或类型下拉。所有动态内容用 `App.escapeHtml`；禁用字段与隐藏区块必须真正不可见，页面级 `[hidden]` 规则不得被容器 `display` 覆盖。窄屏 <=900px 左栏收窄至 200px，<=640px 才上下堆叠，640px 以上保持左右工作台；表单字段在 <=860px 转单列，底部操作条在窄屏保持普通 footer 布局。

## 静态资源与图表

- ECharts 使用本地 vendor 版本；图表颜色从 CSS 令牌运行时读取，不在 JS 中维护十六进制颜色副本。
- 静态资源 URL 带版本参数；资源修改后同步更新版本，避免浏览器缓存旧文件。
- 身材页趋势折线五档（周 / 月 / 两月 / 半年 / 一年）共用同一套图表样式：线宽 2.5、圆点 5px、点上数值标签、渐变面积、axis tooltip，不得为某一档单独关标签、改点型或换配色；点位变密时只由 ECharts `labelLayout.hideOverlap` 统一避让重叠标签。两月档为最近 60 天逐日 1 点，无记录为 null 断线。
