# 前端设计与实现规范

本文档记录已实现页面的组织方式，以及新增页面应复用的视觉、布局和交互规范。系统整体架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 页面组织

- 页面模板位于 `app/templates`，公共布局由 `base.html` 提供；公共行为位于 `app/static/js/common.js`。
- 页面资源按模块放在 `app/static/css/pages/` 和 `app/static/js/`，通过 `extra_css`、`extra_js` 按需加载。
- 业务页复用 `render_page` 注入登录用户、导航高亮、面包屑、今日信息和常量。
- 三个运动页面统一提供计划、记录、导入和记录管理入口；状态记录页和 AI 助手页按各自业务流程组织。
- 技能管理页 `/agent/skills` 挂在侧栏「AI助手」分组下，`active=agent_skills`，分组头与子项同时高亮；页面与 AI 对话页一致，为整页白底铺满、左侧技能导航 + 右侧编辑区的连续工作台，无外层灰底与卡片，窄屏在 640px 以下才纵向堆叠；交互与样式分别由 `agent_skills.js`、`agent_skills.css` 承载。
- 状态记录页为三卡片纵向堆叠（`three-row-stack`，卡片与内容随宽度自适应铺满）：月历 → 当日状态 → 全部记录。「当日状态」按 `STATE_TYPES` 顺序渲染各记录项块（食欲 / 肌肉疼痛 / 炎症 / 情绪 / 恢复），桌面两列网格、每行 2 个记录项，760px 以下单列；每块内联星级（五星 + 「0」最低分按钮，未评存空）+ 自适应高度描述框 + 保存，有记录时块内可删除；新增记录不弹窗，仅列表行内「编辑」走表单弹窗。筛选项与编辑弹窗的记录类型来自服务端 `state_types` / `state_type_labels`，不得在前端另写类型数组；月历阶段图例与页头「结合生理周期阶段」文案按 `/api/state-record/calendar` 的 `cycle_enabled` 显示，非女性账号整块隐藏。
- 报告页 `/reports` 挂在侧栏「运动训练/计划」分组第四项，`active=reports`；顶部 `.seg` 切周报/月报，`.date-nav` 步进周期（周 ±7 天、月 ±1 月，下一周期为未来时禁用），右侧显示「进行中 · 截至 X」与生成/重新生成按钮。主体依次为 4 张 `.stat-card`（次数/时长/活跃天数/热量，delta 文案来自服务端）、叙事卡（headline/summary/周期视角/亮点/留意/下阶段建议/数据说明）、判断依据卡（运动/身体/状态/周期/完整度，其中「周期」块仅在报告存在周期事实时渲染，无数据不显示空块）、历史报告表（查看 + 软删除）。总览页顶部提供「周报」「月报」两个 `btn btn-sm` 入口。页级脚本 `report.js`、样式 `css/pages/report.css`。
- 内置角色页 `/system/personas` 挂在侧栏「系统设置」分组下，`active=system_personas`；复用技能/角色工作台布局：左侧内置角色列表 + 右侧编辑区。右侧依次为基本信息（角色名、不可改的角色键、排序、状态、定位）、提示词、工具勾选、平台技能勾选；工具按只读/交互/写入分组，技能按代码/声明式/平台提示词分组，勾选项显示默认受限/版本。底部提供「恢复默认范围 / 删除 / 保存并生效」，`tool_grants` / `skill_grants` 为 `null` 时展示默认范围，保存显式勾选后锁定为白名单。页级脚本 `system_personas.js`、样式 `css/pages/system_personas.css`、模板 `app/templates/system/personas.html`；管理员门禁与定时任务页一致。
- 定时任务页 `/system/scheduler` 挂在侧栏「系统设置」分组下，`active=scheduler`，分组头与子项同时高亮；主体为任务卡列表（任务名 + 说明 + 表达式中文化 + 下次执行 + 上次结果/耗时/累计次数 + 启用状态，卡片右上次级操作「立即执行 / 编辑 / 停用启用 / 删除」）、新建/编辑弹窗（触发类型 cron/interval/date、表达式、时区、参数）与执行历史表（时间/来源/结果/耗时/摘要 + 分页）。表达式非法时后端返回 400，前端用 toast 直接展示原因，不在本地猜测校验规则。页级脚本 `system_scheduler.js`、样式 `css/pages/system_scheduler.css`、模板 `app/templates/system/scheduler.html`。侧栏「系统设置」分组只对管理员渲染（`render_page` 注入 `is_admin` 后过滤导航），普通用户看不到入口；直接输入 URL 由后端 `AdminGateMiddleware` 返回 403 错误页，前端不做二次权限判断。
- 生理周期页 `/cycle`：仅女性账号可进入，男性与未填性别访问时后端 303 回 `/body`，不渲染本页。左侧月历 + 「全部记录」，右侧为当日详情与「今日 note」上下两张卡片。全部记录用 `.seg` 在「月经记录 / 周期日志」间切换：月经记录表格列为开始日期、结束日期、经期长度、周期长度、查看/编辑/删除；周期日志走 `GET /api/cycle/logs` 服务端分页，列为日期、疼痛、所属经期、note、查看详情。两段都复用公共 `.tbl` + `.pagination`，空态用 `.empty-state`。详情依次为日期/阶段标签、激素水平、疼痛程度、周期概览；激素文案由服务端按阶段日序给出，固定两行（`.dd-hormone` 用 `white-space: pre-line` 原样换行），不展示「运动建议」；疼痛星级只在 recorded 经期（`period_state === 'recorded'`）出现，推算经期、预测经期及其他阶段整块隐藏。「今日 note」固定今天、不随月历翻月，文本域最多 255 字，保存写 `/api/cycle/note/{today}`，非经期日保存时后端把疼痛与归属置 null。

## 视觉与组件规范

- 颜色、圆角、间距和状态色统一定义在 `tokens.css`；CSS 使用 `var(--令牌)`，JS/ECharts 使用 `App.cssVar`。
- 角色会话：对话页「新建角色会话」打开角色选择弹窗（列表项展示角色名、来源「内置/我的角色」与定位，选中后创建会话）；创建后交互与普通会话一致，侧栏会话项带蓝绿色描边徽标（人形图标 + 角色名），会话内不提供切换入口。平台内置角色当前为营养师、电子私教、健身教练、健康档案测试，均由角色列表接口返回，前端不写死。健康档案测试角色一次只做一个专项，逐题调用 `ask_user`，同一轮内连续出现多张问答卡片，每答一题后下一题卡片接续显示；历史消息由 `build_turns` 还原为多个 `ask` 段。输入 `/` 的斜杠建议改走 `GET /api/agent/skills/available?persona_id=`，只列当前角色可用技能；10 个档案专项只对健康档案测试角色出现，`定制健身计划` 只对健身教练角色出现。专项技能展示名统一带 `测试-` 前缀，斜杠命令仍为 `/目标档案`、`/健身档案` 等原名称。
- 页面沿用系统字体、公共按钮、输入框、标签、卡片、表格、分页、空态和弹窗组件，不重复实现公共交互。
- 计划态使用 `--state-plan`，记录态使用 `--state-record`；运动编码色使用各自语义令牌，不得用品牌色替代。
- 状态记录类型标签固定四色：食欲 `tag-appetite`（橙）/ 肌肉疼痛 `tag-gray`（中性灰）/ 炎症 `tag-inflam`（红）/ 情绪 `tag-mood`（低饱和紫），底色、文字色、圆点分别取自 `--tag-*-bg` / `--tag-*-fg` / `--tag-*-dot`。
- 缺失数据显示“—”，空列表使用空态，不使用假数据占位。
- 报告页 delta 文案不使用 `delta-up/down` 的红绿语义（训练量上升不一定是“坏”）：统一 `.rp-delta` 灰色，仅上升用 `--color-accent-strong` 强调；周期视角块用 `--phase-menses` 左侧竖线，不使用整块彩色背景。
- 用户文本插入 HTML 前必须经过 `App.escapeHtml`；接口请求和提示统一使用 `App.api`、`App.postMultipart`、`App.toast`。

## 布局与响应式

- 业务页沿用固定侧栏、顶栏和内容区布局；主操作紧邻页面标题，内容按任务分区排列。
- 宽表只允许表格容器横向滚动，不得撑宽整页；弹窗必须限制宽度和高度。
- 页面必须适配桌面、中屏和窄屏；标题、工具栏、表单、表格、弹窗及动态内容在窄屏仍可操作，不得互相遮挡。
- 新增页面应优先复用现有布局和组件，只有现有结构无法满足需求时才增加模块级样式。
- 报告页：hero 为「左叙事 + 右生成信息/操作」两列，生成信息只显示生成时间，不显示模型名；叙事分区两列（亮点/留意），下阶段建议与数据说明跨两列；<=1100px 叙事分区与依据卡转单列，<=640px hero 转单列。依据卡为 2 列网格（`rp-ev`），每块内 `rp-ev-row` 左标签右数值，窄屏单列。
- 个人信息页 `/profile` 与健康档案页 `/profile/health-profile` 挂在侧栏「个人信息」分组下（`active` 分别为 `profile_basic` / `health_profile`，分组头与子项同时高亮）。账号资料页保持左栏只读概览 + 右栏基本资料/修改密码。健康档案页固定展示可用专项卡（女性 10 个；男性与未填性别 9 个，不含生理期；2 列 masonry，<=980px 单列）：卡头为专项名 + 生成时间/题数 + 状态；已建立卡默认只读展示题目与答案全文（`white-space: pre-wrap`，未答显示「—」），未建立卡展示专项说明与「新增/编辑」入口。卡头按钮统一为「新增/编辑」，点击打开弹窗而不是卡内展开：弹窗内问题文字与回答均可编辑，末尾虚线「+ 添加一个问题」可自定义追加，最多 10 题；弹窗底部为取消/保存，保存提交整卡后刷新。页头四项概况（已建立专项/累计问题/已填写回答/最近更新）只读，清空档案走统一 `App.confirmDialog` 二次确认。页面不展示 `aspect`、`skill_key`、`set_id` 等内部字段，只使用接口返回的 `name/items`。页级脚本 `health_profile.js`、样式 `pages/health_profile.css`。子项 key 不得叫 `profile`，否则会覆盖 `PAGE_TITLE` 的面包屑标题。
- AI 助手页：空会话时欢迎语与输入框在对话区成组垂直居中，出现消息后输入框沉底；输入框底行左端为「联网」开关（地球图标 + 文案胶囊，默认关闭；开启后描边与底色切到强调色），模型选择位于输入框底行、发送按钮左侧；服务端未配置联网密钥时按钮置灰并提示配置；开关只存在内存，刷新页面回到关闭，开启状态对下一次发送、重新生成、续写与作答生效。输入框为描边叠加轻外阴影，不另设卡片底色。空态欢迎页输入框较高；进入对话后默认高度比空态低 1/3，输入换行随内容自动增高，最高不超过半屏（50vh）。正文列与输入框同宽、居中并左右对齐；AI 正文按 Markdown 渲染、无气泡描边，相邻段落以发丝灰线分隔；宽表只在表格容器内横向滚动，不撑宽正文区。每条完成的 AI 回答正文下方置灰色圆形小图标按钮（复制、重新生成），悬浮提示对应文案；复制取该条回答原始 Markdown 纯文本，重新生成仅作用于最近一轮。生成过程中发送按钮原地变为停止按钮（方形图标 + 深色底、尺寸与位置不变，避免跳动），再次点击即中断本次生成；中断后的回答末尾显示“已停止生成”，并多出一个胶囊形「继续」按钮，与「重新生成」并列——「继续」接着写被中断的内容，输入框只发“继续/接着/continue”这类短语等同于点它。会话项尾部为三点按钮，弹出 body 级菜单（置顶/取消置顶、重命名、删除会话）；置顶会话用浅蓝绿底、左侧 2px 强调线和标题右侧书签标识区分，并在列表顶部单独成「置顶」组，未置顶项归入「全部会话」组；两组内均按最近消息时间倒序，发送消息收到 SSE `start` 后立即刷新活动时间并前移；删除先弹确认框提示不可找回，确认后硬删除。输入框 placeholder 提示 `/技能名 自然语言`；输入 `/` 时在输入框上方浮出当前可用技能建议（平台与我的 active 技能），按名称/键/别名过滤，↑↓ 选择、Enter/Tab 插入 `/技能名 `、Esc 或继续输入正文后关闭，建议面板不占对话区高度；斜杠技能轨迹显示“正在运行/已运行”，技能结果折叠区展示技能名、版本、期间、输出表、caveats 和解析 meta；提示词技能折叠区只显示“已加载技能提示词，按指令生成回答”与耗时，不渲染空输出表；普通只读工具仍显示“正在查询/已查询”。一条 AI 回答按 turn 建模（正文段 + 工具轨迹），流式、重新生成与历史恢复共用同一套渲染器与事件 reducer；工具名与展示标签由服务端下发，前端只保留 `kind → 文案` 映射，不在前端另存工具名表，正文增量按动画帧合并渲染。中途提问在正文中间插入问答卡片（`ask` 段）：浅灰底、1px 发丝描边、与正文同列，问题在上、最多 4 个胶囊选项在下、再下一行输入框与「发送」，「发送」右侧是文字按钮「跳过」；单选点击即提交，多选先选后提交，也可直接键入，跳过提交 `skip_ask=true`；已答卡片显示“已回复 + 答案”，跳过的显示“已跳过 + 未作答，按已有信息继续”，待答时隐藏「重新生成」，主输入框同样可作答。同一轮有多题时题号行显示“第 N 题”，并支持回溯：待答卡片题号行右侧是「上一题」，已答卡片是「修改」，点击后该卡片就地切成预填原答案的输入框（Enter 保存、Esc 取消），保存调 `messages/ask-update` 并按题号写回，成功后标“已修改”；回改入口只在本轮仍有待答问题时出现，本轮收口后一并隐藏。选中会话同步进 URL 与 localStorage，进入页面自动恢复上次会话（切页、刷新不再退回新建态）；历史里若该会话仍在服务端生成，末尾显示“正在生成…”占位并轮询，生成结束后自动替换为完整回答。侧栏「新建会话」只回到空白新建态、不调用接口：首条消息发送时才落库，因此连点新建也不会在列表里堆出多条空会话。
- 技能管理页：整页白底铺满，左侧技能导航与右侧编辑区以发丝线分隔，不设页面灰底、外层卡片、阴影或悬浮面板。左侧为平台/我的技能分组、数量、状态与斜杠命令，顶部为「新建技能」入口；右侧为固定工作头（技能名、斜杠命令、实现类型与版本），中间编辑器独立滚动，底部操作条作为工作区 footer 常驻，不再吸底悬浮。平台技能字段只读（`can_edit=false`），用户技能按状态显示草稿/已发布/已停用，删除权限单独由 `can_delete` 控制。用户技能只编辑提示词文本域；平台代码/声明式/提示词技能只读展示，不提供用户声明式模板、格式化或类型下拉。所有动态内容用 `App.escapeHtml`；禁用字段与隐藏区块必须真正不可见，页面级 `[hidden]` 规则不得被容器 `display` 覆盖。非女性账号的平台技能列表不展示「测试-生理期档案」。窄屏 <=900px 左栏收窄至 200px，<=640px 才上下堆叠，640px 以上保持左右工作台；表单字段在 <=860px 转单列，底部操作条在窄屏保持普通 footer 布局。
- 内置技能管理页 `/system/skills`：挂在「系统设置 → 内置技能」，沿用技能工作台左栏 + 右编辑区与常驻 footer，不另起页面骨架。左栏按「提示词技能 / 声明式技能 / 代码技能」分组并显示数量，进入页面优先选中提示词/声明式技能，没有时选中首个代码技能；新建时先选类型（提示词 / 声明式）。代码技能定义区只读，并在文本域上方常显「代码技能由平台代码注册」说明；名称、斜杠别名、描述、分类与状态可编辑，底部按钮为「保存信息」，技能键只读、删除隐藏。提示词技能用纯文本提示词文本域，隐藏试运行参数区，声明式技能按「基本信息 / 技能定义 / 试运行参数 / 运行记录」分区。提示词/声明式底部为「校验内容 / 试运行 / 运行记录 / 删除 / 保存并生效」；代码技能隐藏「校验内容 / 删除」，保存按钮为「保存信息」。声明式定义使用等宽字体文本域，代码技能只读定义高度收至约 132px；试运行结果只展示 summary、输出表与 caveats，不直接倾倒 JSON。字段网格宽屏三列、<=1080px 两列、<=860px 单列；空分组只显示「暂无代码技能」等提示，不暴露内部脚本路径。

## 静态资源与图表

- ECharts 使用本地 vendor 版本；图表颜色从 CSS 令牌运行时读取，不在 JS 中维护十六进制颜色副本。
- 静态资源 URL 带版本参数；资源修改后同步更新版本，避免浏览器缓存旧文件。
- 局域网 IP + HTTP 属于非安全上下文：不得直接依赖 `crypto.randomUUID`、`crypto.subtle` 等仅安全上下文可用的 API，需提供降级实现（`crypto.getRandomValues` 不受此限制）；`navigator.clipboard` 必须保留 `execCommand` 兜底。
- 身材页趋势折线五档（周 / 月 / 两月 / 半年 / 一年）共用同一套图表样式：线宽 2.5、圆点 5px、点上数值标签、渐变面积、axis tooltip，不得为某一档单独关标签、改点型或换配色；点位变密时只由 ECharts `labelLayout.hideOverlap` 统一避让重叠标签。两月档为最近 60 天逐日 1 点，无记录为 null 断线。
- 身材页「全部记录」按日期合并 4 组记录，固定列为日期、身高、体重、体脂率、臂围、胸围、腰围、臀围、大腿围、小腿围、操作；`TABLE_COLS` 顺序必须与表头一致，新增/删除列时同步空态 `colspan`。
